# Discord Mute Bot — вечный онлайн 24/7 на Render (бесплатно)

Бот с командой мута на **любое время**, с аллиасами и автокомплитом.
Внутри — keep-alive HTTP-сервер, чтобы Render никогда не гасил инстанс.

## Что умеет

- `/mute`, `/мьют`, `/мут`, `/таймаут` — четыре slash-команды, один обработчик.
  Аллиасы добавляются одной строкой в массиве `MUTE_ALIASES` (файл `commands.js`),
  и Discord сам показывает их в меню «/» при вводе.
- Текстбокс с выбором участника, любое число, единица времени с подсказками:
  секунды / минуты / часы / дни.
- Нативный тайм-аут Discord (виден участнику в профиле). Лимит Discord API —
  28 дней: если запросить больше, бот выдаст максимум и честно напишет об этом.
- `/unmute`, `/размьют`, `/размут` — снять мут (защита от мута владельца/самого себя,
  проверка иерархии ролей и наличия мута).
- `/loopclear`, `/лупклир` — гениальная очистка канала. Удаляет сообщения: свежие
  пачками (как внутренний аналог bulkDelete), старые 14+ дней — по одному, быстро,
  принудительно. Можно указать `ник` (только его сообщения) или оставить пустым — всех.
  Опционально `count` от 1 до 1000 — сколько сообщений удалить (по одному проходу).
  В канале может работать только один лупклир; повторный запуск с теми же настройками
  не пересоздаёт, а конфликтующий фильтр предлагает через `/stoploopclear` остановить.
- `/stoploopclear`, `/стоплупклир` — останавливает очистку. С `ник` останавливает лупклир
  этого участника, без — весь, что качается в канале.
- `/spvkban`, `/спвкбан` — бан игрока в Roblox по нику через Open Cloud (Open Cloud Ban API).
  Нужен `ROBLOX_API_KEY` с правом `universe.user-restriction:write` и `ROBLOX_UNIVERSE_ID`.
  Время в часах, 0 = перманент. `/spvkunban`, `/спвкразбан` — разбан по нику.
- `/gifblacklist`, `/гифблеклист` — **чёрный список гифок**. Добавил ссылку на гифку —
  и бот удаляет её из чата сразу, как только кто-то её пришлёт (ссылкой, эмбедом или
  даже залив файл заново). Внутри — `add`, `remove`, `addwhitelist`, `removewhitelist`,
  `list`; данные лежат в `configs/gifblacklist.json`. Подробности — в разделе ниже.
- **Мут за спам гифками:** 3 отправленные заблокированные гифки (в течение суток) →
  автотайм-аут на **30 минут** по причине «Спам запрещенными гифками». Нарушителю —
  в ЛС, модераторам — в мод-лог-канал (`LOG_CHANNEL_ID`).
- `/nametouserid`, `/никвиди` — ник Roblox → Roblox ID (заодно дисплей ник и аватарка).
- `/getrobloxinfo`, `/роблоксинфо` — карточка игрока Roblox: большая аватарка 420×420,
  ник, дисплей ник, возраст аккаунта, подписки, подписчики и друзья (каждое — ссылка
  на нужную вкладку страницы друзей) плюс ссылка на профиль.
- Анти-сон в три слоя + сторожевой пёс: самопинг раз в 4 минуты, внешний автобот из
  GitHub Actions раз в 5 минут, а если gateway всё равно лёг — перезапуск подключения
  и, если не помогло, `exit(1)` с перезапуском контейнера Render. Больше не «молча»:
  о каждом подъёме бот пишет в мод-лог-канал.
- Анти-падение: обработка всех ошибок, авто-реконнект gateway, keep-alive сервер
  на порту 10000. Прогресс лупклира выводится обновлением одного сообщения, так что
  видно, сколько уже удалил.

## 1. Discord Developer Portal

1. Зайди на https://discord.com/developers/applications → **New Application**.
2. Вкладка **Bot** → **Reset Token** → скопируй токен → это `DISCORD_TOKEN`.
3. Вкладка **General Information** → **Application ID** → это `CLIENT_ID`.
4. Вкладка **Bot** → **Privileged Gateway Intents** → включи **Message Content Intent**.
   Он нужен фильтру гифок (`/gifblacklist`): без этого intent Discord отдаёт боту
   пустые `content`, `embeds` и `attachments`, а при старте вообще рвёт подключение
   (close code 4014), и бот не поднимется. Слэш-командам intent не нужен, а вот
   фильтру сообщений — жизненно необходим.

## 2. Инвайт бота с правами

OAuth2 → URL Generator:

- Scopes: `bot` + `applications.commands`
- Bot Permissions: `View Channels`, `Send Messages`, `Embed Links`,
  `Manage Messages` (нужно, чтобы удалять гифки из блеклиста),
  `Read Message History` (нужно, чтобы читать сообщение по ссылке),
  `Moderate Members` (или **Administrator** — тогда вообще все права)

Готовый шаблон ссылки (подставь свой ID):

```
https://discord.com/oauth2/authorize?client_id=ТВОЙ_CLIENT_ID&scope=bot+applications.commands&permissions=1099511720960
```

(`permissions=8` вместо длинного числа — это Administrator, если хочешь все права разом.)

**ВАЖНО:** после инвайта зайди в Настройки сервера → Роли и перетащи роль бота
ВЫШЕ ролей участников, которых он будет мутить. Discord не даёт модерировать
того, чья роль выше роли бота.

## 3. Деплой на Render (free, 24/7)

1. Залей эту папку в GitHub-репозиторий.
2. https://render.com → **New** → **Web Service** → выбери репозиторий.
3. Настройки:
   - Runtime: **Node**
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: **Free**
4. Environment → Add Environment Variable:
   - `DISCORD_TOKEN` — токен бота
   - `CLIENT_ID` — ID приложения
   - `GUILD_ID` — ID сервера (опционально, для мгновенной регистрации команд)
   - `GIF_BLACKLIST_LOG_CHANNEL_ID` — канал для лога удалённых гифок (опционально)
   - `LOG_CHANNEL_ID` — мод-лог: баны, разбаны, муты за гифки, перезапуски бота (опционально)
5. Deploy. В логах должно появиться:
   `[keep-alive] HTTP-сервер слушает порт 10000` и `[bot] вошли как ...`

> Можно и через Blueprint: Render подхватит `render.yaml` автоматически
> (New → Blueprint), переменные всё равно вписать руками.

## 4. Чтобы не засыпал и не ложился молча (анти-сон в три слоя + сторожевой пёс)

Бесплатный инстанс Render засыпает через **15 минут без входящего трафика**, а сон
рвёт gateway Discord — снаружи это выглядит как «бот молча лёг». Теперь от этого
три независимых слоя защиты:

| Слой | Что делает | Где живёт |
|------|------------|-----------|
| 1. HTTP-сервер | держит порт открытым и отдаёт `/healthz` с состоянием бота | `keepalive.js` |
| 2. **Внутренний автобот** | каждые 4 минуты пингует свой `/healthz` — трафик есть, сон не начинается | `keepalive.js` |
| 3. **Внешний автобот** | GitHub Actions дёргает `/healthz` каждые 5 минут — поднимает инстанс, даже если процесс умер | `.github/workflows/keepalive.yml` |

Свой URL для внутреннего автобота искать не нужно: Render сам подставляет
`RENDER_EXTERNAL_URL` (можно переопределить переменной `PING_URL`).

**Внешний автобот — включить один раз (полминуты):**

1. Залей репозиторий на GitHub — папка `.github/workflows` должна попасть в репозиторий.
2. GitHub → репозиторий → **Settings → Secrets and variables → Actions → Variables**.
3. **New repository variable**: Name = `RENDER_URL`, Value = `https://имя-сервиса.onrender.com`.
4. Вкладка **Actions** → workflow **keepalive** → **Run workflow** — проверить руками.

GitHub под нагрузкой может задержать пинг на пару минут, поэтому слой 2 (внутри бота) и нужен.

**Сторожевой пёс — чтобы «молча» больше не было:**

- gateway не готов дольше 3 минут → бот делает `destroy()` + `login()` заново;
- 3 таких перезапуска за 30 минут → `exit(1)`, и Render поднимает контейнер сам;
- RSS выше 460 МБ (Render при OOM убивает контейнер молча) → выходим сами;
- замер лага event loop и детект «инстанс спал» — в лог Render и в `LOG_CHANNEL_ID`;
- каждый подъём бота пишет в мод-лог-канал `🟢 Бот на связи: …`.

Состояние всегда видно в браузере: `https://имя-сервиса.onrender.com/` отдаёт JSON с
`status`, `wsPingMs`, `memoryMb` и блоком `keepAlive` (`selfPings`, `sleeps`,
`recoveries`, `lastSelfPingAt`). Ответ `503` на `/healthz` = инстанс жив, но gateway
ещё поднимается. Хочешь четвёртый слой — оставь внешний пингер (cron-job.org /
UptimeRobot) на тот же URL: он не мешает.

Render даёт **750 бесплатных часов в месяц** — ровно один сервис 24/7 на весь месяц.

## 5. Локальный запуск

```bash
npm install
cp .env.example .env   # и заполнить токены
npm run register       # регистрация команд (мгновенно, если задан GUILD_ID)

```

## `/gifblacklist` — чёрный список гифок

Бот следит за сообщениями и **сам удаляет** те, где есть гифка из блеклиста: и ссылка
в тексте, и автопревью/эмбед, и вложение (тот же файл, залитый заново). Правки сообщений
тоже проверяются — иначе блеклист обходится «дописал ссылку после отправки».

```
/gifblacklist add                          ← откроется окошко «вставь ссылку»
/gifblacklist add ссылка:https://images-ext-1.discordapp.net/external/…/15LKtkqmWrMszDt.mp4
/gifblacklist add ссылка:https://static.klipy.com/ii/…/15LKtkqmWrMszDt.mp4
/gifblacklist add сообщение:https://discord.com/channels/…/…    ← ссылка на сообщение с гифкой
/gifblacklist remove номер:1
/gifblacklist remove ссылка:https://…      ← достаточно любой ссылки на ту же гифку
/gifblacklist addwhitelist участник:@ник
/gifblacklist addwhitelist роль:@роль
/gifblacklist removewhitelist участник:@ник
/gifblacklist removewhitelist роль:@роль
/gifblacklist list                         ← что в блеклисте и вайтлисте
```

Плюс две **контекстные команды**: ПКМ по сообщению → «Приложения» →
**Gif Blacklist Add** / **Gif Blacklist Remove**. Это и есть «ответить командой на
сообщение»: слэш-команда не знает, на какое сообщение её вызвали, а контекстная знает —
и сама вытащит из сообщения все гифки (ссылки, эмбеды, вложения).

### Почему ловится одна и та же гифка под разными ссылками

В блеклист пишется не строка, а набор подписей (`gifblacklist.js`): «хост + путь»,
длинные хеш-токены из пути, имя файла, а для прокси Discord — ещё и внутренняя
(оригинальная) ссылка. Поэтому одна и та же гифка ловится, приди она прямой ссылкой
`static.klipy.com/ii/<id>/…`, через прокси `images-ext-1/-2.discordapp.net/external/<hmac>/https/…`,
с query-подписью `?ex=…&is=…&hm=…` или с другого домена прокси. Второй эшелон: при
`add` бот скачивает файл (до 16 МБ) и запоминает `sha256` + размер — если тот же файл
зальют заново (новый URL вложения), он всё равно удалится.

### Вайтлист

`addwhitelist` принимает и участника, и роль — можно указать оба сразу. Владелец
сервера и участники с правом **Administrator** блеклист игнорируют всегда
(константа `BYPASS_ADMINS` в `gifblacklist.js` — поставь `false`, если не нужно).

### Мут за спам гифками

Три отправленные заблокированные гифки за сутки — и бот сам выдаёт тайм-аут на
**30 минут** с причиной «Спам запрещенными гифками» (константы `GIF_STRIKE_LIMIT`,
`GIF_STRIKE_WINDOW_MS`, `GIF_STRIKE_TIMEOUT_MS`, `GIF_STRIKE_REASON` в `index.js`).
Счётчик страйков живёт в том же `configs/gifblacklist.json` (секция `strikes`) и
сбрасывается после мута и через сутки. В чат бот при этом ничего не пишет: причина
уходит нарушителю в ЛС, а модераторам — в мод-лог-канал (`LOG_CHANNEL_ID`). Текущие
страйки видны в `/gifblacklist list`.

### Где лежат данные

`configs/gifblacklist.json` — секции `gifs`, `whitelist.users`, `whitelist.roles`.
Файл можно править руками и коммитить в репозиторий: тогда после редеплоя список
восстановится. Путь переопределяется переменной `GIF_BLACKLIST_PATH`.
**Важно:** на бесплатном Render диск эфемерный — то, что добавили через команды,
потеряется при редеплое/рестарте инстанса (коммит файла или постоянный диск решают это).

### Что нужно для работы

1. **Message Content Intent** — Developer Portal → Bot → Privileged Gateway Intents.
2. Права бота: `Manage Messages` (удалять сообщения), `Read Message History` (читать
   сообщение по ссылке), `View Channels`, `Embed Links`.
3. Бот ничего не пишет в чат: ответы и ошибки команд с гифками видит только тот, кто их
   вызвал (эфемерные сообщения — так же, как у `/spvkban`). Если удаление не удалось,
   пояснение уходит в ЛС тому, кто добавил эту запись в блеклист, а строка
   `[gifblacklist] …` — в консоль Render. Хочешь складывать все удаления в канал —
   задай `GIF_BLACKLIST_LOG_CHANNEL_ID`.

## `/nametouserid` и `/getrobloxinfo` — Roblox-справка

```
/nametouserid ник:Builderman
/nametouserid ник:156
/nametouserid ник:https://www.roblox.com/users/156/profile
/getrobloxinfo игрок:Builderman
/getrobloxinfo игрок:156
```

- `/nametouserid` (`/никвиди`) — ник → Roblox ID. Принимает ник, числовой ID или ссылку
  на профиль; показывает ник, дисплей ник, ID и маленькую аватарку.
- `/getrobloxinfo` (`/роблоксинфо`) — карточка игрока: **большая аватарка 420×420**,
  Ник, Дисплей ник, Возраст аккаунта («7 лет 3 месяца (с 12.03.2019)»), Подписок,
  Подписчиков, Друзей — каждое число кликабельно и ведёт на
  `/users/ID/friends#!/following`, `#!/followers` и `/users/ID/friends` соответственно,
  плюс ссылка «Профиль роблокса» на `/users/ID/profile`.

Обе команды отвечают **эфемерно** — ответ видит только тот, кто ввёл команду.
Аватарка берётся из официального `thumbnails.roblox.com/v1/users/avatar-headshot`
(size `420x420`) — это те самые `tr.rbxcdn.com/.../AvatarHeadshot/Webp/...` ссылки,
только полученные по API, а не собранные руками; если API притих, включается фолбэк
`www.roblox.com/headshot-thumbnail/image?userId=…&width=420&height=420`. Если Roblox
не отдал счётчики (эндпоинты друзей иногда меняются) — вместо числа будет «—»,
команда всё равно покажет остальное.

## Как добавить свой аллиас

Файл `commands.js`:

```js
const MUTE_ALIASES = ['mute', 'мьют', 'мут', 'таймаут', 'банан'];
```

Строчными буквами, без пробелов. Перезапусти — Discord покажет новую команду
в меню «/» автоматически. Все аллиасы делят один обработчик и один автокомплит.

## «Роль бота выше, а мут всё равно не работает»

Частая ловушка: **в списке участников боты всегда висят наверху группой — это не
позиция роли**. Позиция смотрится только в Настройки сервера → Роли.

- Высшая роль бота должна быть СТРОГО выше высшей роли участника (равная — уже не канает).
- Право Administrator **не пробивает иерархию** — оно даёт сами права, но не высоту.
- У бота есть управляемая роль с его именем (создалась при инвайте) — двигать можно и её.
- Владельца сервера не замутит никто и никогда — таков Discord.
- **Других ботов тоже нельзя мутить** — Discord возвращает Missing Access (50013) даже при идеальных ролях. Кик/бан ботам можно, тайм-ауты — нет.

Если API всё равно отказал — в логах Render будет строка `[mute] Discord API отклонил тайм-аут: code=... message=...` с позициями обеих ролей. Она показывает правду со стороны Discord.

## 50013 Missing Permissions при идеальных ролях — требование 2FA

Если роль бота выше, права есть, а API всё равно отвечает Missing Permissions —
на сервере почти наверняка включено **«Требовать 2FA для действий модерации»**
(Настройки сервера → Настройки безопасности). С ним Discord считает, что у бота
нет модерационных прав, пока у **владельца бота** не включена двухфакторная
аутентификация. Решения:

1. Включить 2FA на аккаунте владельца бота (Настройки пользователя → Моя учётная
   запись) — рекомендуется; если у приложения команда разработчиков — 2FA нужна всем.
2. Или выключить требование на сервере.

Бот распознаёт этот случай сам по `mfaLevel` сервера и пишет оба варианта.

Бот пишет диагностику с именами ролей и их позициями (и логирует её в консоль
Render), так что виновника видно сразу.

## Почему он не падает

- HTTP-сервер на порту 10000 → Render видит открытый порт и считает сервис живым.
- Пингер каждые 5 минут → инстанс не засыпает на free-тарифе.
- `process.on(...)` ловит необработанные ошибки → процесс не умирает.
- discord.js сам переподключается к gateway при обрывах сети.
- Даже если процесс упадёт — Render автоматически перезапустит контейнер.
